# 会话文件与大量会话

会话列表右键 → **会话文件**：在系统文件管理器中选中对应的 Codex 原始 JSONL，优先检查当前 API 配置的 sessions/archived_sessions，再检查用户外部 .codex 目录。导入的原始记录也会保留来源路径；分叉后按新的会话 ID 定位。此功能不会创建导出副本。尚未运行、文件删除或不支持的会话会显示说明。

AI 回复记录生成时的模型和推理强度，切换配置不会重写历史标签。旧消息有模型信息时显示模型，没有记录的强度不会推测；完全缺少模型时显示 AI。导入、导出保留这些字段。

## 存储与迁移

- 状态索引仍为用户数据目录的 `state.electron.json`；历史拆分在旁边的 `state.electron.json.messages/`。
- 首次迁移保留 `state.electron.json.before-split.bak`。备份含迁移前的本地对话，不包含之后的新消息。
- 历史文件使用内容哈希命名，先写历史再原子更新索引，保留上一代引用；后台清理不再引用的文件。
- 正常保存由后台线程串行完成，合并等待中的保存；相同历史不重复写入。关闭窗口、退出前等待落盘，失败时保留窗口并提示。
- 冷会话按需加载，已保存的非活动、非运行会话释放消息内存。取消原有的 2,000 条消息截断。
- 左侧列表使用固定行高虚拟化，仅创建可见行和缓冲行。完整快照仅传活动会话历史，其余传摘要；团队模式按需读取完整回复。

迁移后请使用支持此格式的版本。备份或迁移应用数据时，必须将索引与 `.messages` 目录一起复制，不能只复制索引文件。

## 验证

在 src 下运行：

```powershell
npm run build
node --test tests/conversation-scale.test.cjs
node tests/conversation-scale-ui.cjs
npm run test:windows:ui
```

覆盖 1,000 会话迁移、超过 2,000 条消息保留、按需读取、保存合并、不变历史不重写、损坏记录报错、定位缓存失效，以及 10,000 会话虚拟列表滚动、搜索、右键菜单和模型标签。测试使用临时目录，不修改真实用户数据。
